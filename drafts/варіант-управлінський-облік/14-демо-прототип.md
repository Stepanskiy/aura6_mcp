# 14. Демо-прототип управлінського варіанта

Застосунок, який можна показати клієнту. Реалізує концепцію з [12-варіант-управлінський-облік-проєктів.md](12-варіант-управлінський-облік-проєктів.md) і канали з [13-канали-і-власна-модель.md](../13-канали-і-власна-модель.md). Код — у [prototype/](../../prototype/).

## Межі демо

| Є | Немає (свідомо) |
|---|---|
| Каталог SPA, простий вхід без ролей | Ролі, права по фірмах |
| Проєкти: список, створення, копія, картка з медіапланом | Сервер і БД: усе в браузері (localStorage) |
| Імпорт бюджетів з Excel: один файл — багато проєктів, шапки проєктів створюються за кодом | MCP-сервер: чат працює всередині застосунку |
| Фінальні суми з файлу; закриття робіт — окрема дія | Платежі й розподіл FIFO — наступний етап |
| Версії плану (вручну і за порогом), історія змін | Кілька валют |
| Рахунок клієнту за період з бюджетів, мультибренд; друкована форма за шаблоном 1С | Інтеграція з бухгалтерією |
| Звірка план — виставлено — не виставлено | Дані клієнтів: тільки демо-набір |
| Конструктор звітів за період | |
| Помічник у бічній панелі праворуч: відкриває SPA з параметрами ліворуч, даних не бачить | |

Поля — тільки ключові. Проєкт: код, назва, клієнт, бренд, напрям, менеджер, рік, період, статус. Робота: вид робіт, носій, формат, підрядник, період, опис, дохід, затрата, прапорець «закрито».

## Інтерфейс залежить від типу медіа

Картка проєкту показує додаткові вкладки лише тоді, коли вони мають сенс для його медіаплану. Ядро даних однакове, змінюється тільки інтерфейс.

| Вкладка | Коли з’являється | Що показує |
|---|---|---|
| Календар виходів | Є розміщення (ТБ, радіо, OOH, діджитал…) | Флоучарт по носіях: дні / тижні / місяці, лінія «сьогодні», бюджет по періодах, вивантаження в Excel |
| Карта площин | Є зовнішня реклама | Площини на карті (OpenStreetMap), фільтр за містом і форматом, список, адресна програма в Excel |
| Ефективність | Є діджитал | Покази, охоплення, кліки, CTR, CPM, CPC, перегляди / VTR, конверсії / CPA: план від бюджету і факт; графік темпу; таблиця по роботах |
| Рекламні кабінети | Є діджитал | Підключення Meta Ads, Google Ads, TikTok Ads, звіти MEGOGO / Sweet.tv / Ukr.net; зіставлення кампаній з роботами; синхронізація; фактичні витрати → фінальні суми |

Нова вкладка — окремий модуль і один рядок у реєстрі (`src/features/media/registry.ts`); картка проєкту не змінюється.

У демо площини, координати, кампанії і статистика генеруються детерміновано. У робочій системі: адресна програма — від оператора (імпорт або API), статистика — з API платформ, токени — на сервері Аури, модель доступу до них не має.

## Архітектура

```
Браузер
├─ Каталог (вхід у всі SPA)
├─ SPA: Проєкти · Імпорт · Рахунки · Звіти              ← тільки UI
├─ Помічник — бічна панель праворуч, доступна з будь-якої SPA
├─ Контракт запуску: маршрут + параметри (shell/routes.ts)  ← прообраз open_* tools MCP
├─ Сховище з правилами запису (store.ts)                ← прообраз ядра на сервері
│    історія змін · версії за порогом · заборона видаляти виставлене · перевірка рахунків
└─ Адаптер LLM (llm/openrouter.ts) ──► OpenRouter (Qwen / Gemma, перемикається в налаштуваннях)
```

Правила запису зосереджені в одному місці — сховищі, а розрахунки — в чистих функціях (`domain/calc.ts`). При переході на сервер вони переносяться без змін, а SPA замість сховища викликають API.

## Модель у демо

| Де | Що робить модель | Що бачить |
|---|---|---|
| Імпорт Excel | Пропонує структуру аркуша: рядок заголовків, яка колонка що означає, які рядки пропустити. Зіставляє незнайомі назви з довідниками | Зразок ~30 рядків файлу і назви довідників |
| Чат | Вибирає SPA і параметри зі слів користувача | Тільки розмову; результат tool — `{"status":"opened"}` |

Суми модель не переписує: розбір застосовує детермінований код до всіх рядків. Розпізнаний формат зберігається як шаблон — наступний такий файл імпортується без моделі. Обидва екрани показують, що саме отримала модель і скільки токенів це коштувало.

Даних клієнтів у демо немає, тому використовується загальнодоступний API без ізоляції (рішення в [07](../07-рішення-і-відкриті-питання.md)).

## Демо-дані

Український рекламний ринок: активні рекламодавці та їхні бренди, медіахолдинги й селлери, оператори зовнішньої реклами, діджитал-платформи; носії, формати. ~40 проєктів 2025–2026 років, частина робіт закрита, частина виставлена. Суми вигадані. Генеруються детерміновано — «Скинути демо-дані» повертає той самий набір.

Зразки файлів у `prototype/samples/`: два бюджети різних форматів (новий формат розпізнає модель) і файл фінальних сум.

## Сценарій демо (12 хвилин)

1. Каталог: показники агенції, перелік застосунків.
2. Імпорт `бюджети-формат-A.xlsx`: модель розбирає структуру, незнайомі носії зіставляються з довідником, створюються п’ять проєктів. Панель «Що бачила модель» і вартість запиту.
3. Імпорт `бюджети-формат-B.xlsx` іншого формату; збереження шаблону; повторний імпорт без моделі.
4. Картка проєкту: медіаплан, маржа, редагування → автоматична версія плану за порогом, порівняння з планом, історія змін.
5. Фінальні суми з файлу: відхилення від плану; закриття робіт окремою дією.
6. Рахунок клієнту за вересень (Rozetka або Епіцентр — там є невиставлені роботи); друкована форма; звірка «не виставлено».
7. Конструктор звітів: маржа по клієнтах, медіа по місяцях; вивантаження в Excel.
8. Медійні вкладки: LFC-0018 → «Карта площин» (Київ, 54 площини) і «Календар виходів»; RZT-0021 → «Рекламні кабінети»: підключити Meta і TikTok, синхронізувати, «Застосувати фактичні витрати як фінальні суми» → «Ефективність»: план / факт, темп.
9. Помічник (панель праворуч): «яка маржа по клієнтах за 3 квартал 2026?» → ліворуч відкривається звіт, розмова лишається; панель «Що отримала модель» — жодних сум.

Для кроків 2–3 і 9 потрібен ключ OpenRouter. Без ключа імпорт працює на евристиці за назвами колонок (зразки розпізнаються правильно), але різні написання носіїв («Ютуб», «1+1») створюються як нові записи — їх зіставляє саме модель.

## Запуск

```
cd prototype
npm install
npm run dev        # http://localhost:5173
npm run samples    # перегенерувати зразки Excel
npm run build      # статична збірка в dist/ — можна розмістити на будь-якому хостингу
```

Ключ OpenRouter і модель задаються в «Налаштуваннях» і зберігаються тільки в браузері.
