# 3. Стек технологій

## Рекомендація: TypeScript від початку до кінця

Причини:
- найзріліші MCP SDK (`@modelcontextprotocol/sdk`, `@modelcontextprotocol/ext-apps`);
- один і той самий код і контракти для сервера, MCP Apps і користувацьких SPA;
- LLM найкраще генерують саме TS/React — важливо для SPA, які користувачі створюють самі.

| Шар | Вибір |
|---|---|
| Сервер | Node.js 22 + TypeScript, Fastify або Hono |
| Контракти | Zod-схеми як єдине джерело правди. З них генеруються JSON Schema для MCP tools, OpenAPI і клієнтський SDK |
| БД | PostgreSQL з RLS; Kysely або Drizzle (типізований SQL, без важкої ORM). Гроші тільки в `numeric` і decimal.js, ніколи у float |
| Регістри | Таблиці рухів тільки з дописуванням + таблиці підсумків або матеріалізовані залишки. Регістри відомостей — темпоральні таблиці |
| Доступ | Політики в коді та RLS як друга лінія захисту; OpenFGA, якщо звʼязки «співробітник → відділ → проєкт» ускладняться |
| Фонові задачі | Graphile Worker або pg-boss; Temporal, якщо workflow підписів стануть складними |
| Автентифікація | OIDC-провайдер: Keycloak (PoC) або Entra ID (продакшен, якщо є M365). MCP-сервер — OAuth Resource Server |
| Аналітика | Документовані view в окремій схемі; DuckDB або Cube, якщо обсяги виростуть |
| SPA | React + Vite + shadcn/ui + TanStack Table або AG Grid (бюджети, табличні частини) |

## Альтернативи

- **.NET** — має сенс, якщо в команді сильні C#-розробники.
- **Python** — не рекомендується для ядра з такою кількістю транзакційної логіки.

## Keycloak

- Open source, ліцензія Apache 2.0, проєкт Red Hat / CNCF. Безкоштовний без обмежень за кількістю користувачів, зокрема в продакшені. Образ `quay.io/keycloak/keycloak` публічний.
- Платити треба тільки за сервер, де він працює. Для PoC — та сама машина, що й PostgreSQL.
- Реальна «ціна» в продакшені — підтримка самотужки: оновлення, бекапи, моніторинг. В Entra ID за це відповідає Microsoft, і він, швидше за все, вже оплачений у ліцензіях M365 разом з усіма співробітниками та відділами.
- Код Аури від вибору не залежить: обидва — стандартні OIDC-провайдери, перемикання конфігурацією.
