# 7. Рішення і відкриті питання

Загальні рішення, що не залежать від варіанта. Рішення окремих варіантів — у їхніх папках: [варіант з ОСВ](варіант-облік-з-осв/рішення-і-відкриті-питання.md), [управлінський облік](варіант-управлінський-облік/12-варіант-управлінський-облік-проєктів.md#рішення).

## Прийняті рішення

| Дата | Рішення | Чому |
|---|---|---|
| 2026-10-26 | Рішення з 1С напряму не копіюються. Документація й конфігурація Аури 3 — орієнтир щодо функціоналу, джерело тестових даних і еталон для звірки цифр | Аура 6 — нова концепція; модель даних, процеси й алгоритми проєктуються заново |
| 2026-10-26 | Запис — один виклик, без превʼю проводок. Контроль цілісності повністю на сервері; ключ ідемпотентності на кожному записі | Превʼю ніхто не перевірятиме; ідемпотентність потрібна, бо LLM-клієнти повторюють виклики |
| 2026-10-26 | Ядро — REST + типізований SDK; MCP, MCP Apps, Skills — адаптери | Незалежність від еволюції протоколів і клієнтів |
| 2026-10-26 | Чутливі модулі (зарплата, кадри, дивіденди) — SPA, які MCP лише запускає; дані йдуть напряму браузер ↔ Аура | Дані не проходять через модель і інфраструктуру LLM-провайдера |
| 2026-10-26 | Для PoC — Keycloak у Docker | Безкоштовно, без погоджень з IT; код від вибору IdP не залежить |
| 2026-10-26 | Звіти не переносяться 1:1; на сервері лишаються тільки регламентні (Баланс, ФінРез, ДДС) | Більшість із 237 звітів — варіанти; ad-hoc звіти генерує LLM над analytics-view |
| 2026-10-26 | Стенд PoC — VPS-118217 на vpsag.com (2 ГБ RAM), Docker Compose: PostgreSQL + Keycloak + Caddy | Сервер уже є; ресурсів для PoC достатньо впритул |
| 2026-10-26 | Неактивний бот Freqtrade видалено з сервера | Займав місце; API-ключі біржі не повинні лежати поруч із публічним стендом |
| 2026-10-30 | У прототипі модель — тільки навігатор: MCP-tools лише запускають SPA, облікові дані до моделі не потрапляють. MCP-адаптер не залежить від модулів читання даних | Найсуворіший варіант ізоляції. Якщо він працює, послаблення для окремих модулів буде свідомим рішенням, а не вимушеним |
| 2026-10-30 | Фірма — балансова одиниця. Права задаються по фірмах і зберігаються в БД Аури; Keycloak лише засвідчує користувача і має одну роль `aura_admin` | Права по фірмах мають бути доступні RLS і змінюватись без IdP |

## Відкриті питання

| Питання | Від кого / як закривається |
|---|---|
| Домен для стенда: власний чи тимчасово sslip.io | Власник продукту |
| IdP для продакшену: Entra ID чи Keycloak (чи є M365 з потрібними ліцензіями) | Власник продукту / IT |
| Вивантаження даних 2–3 організацій за рік | Адміністратор 1С |
| Сценарії для оцінки PoC (20–30 фраз з очікуваним результатом) | Носій домену; перші 10 — до старту |
| Чи працює прямий `fetch` з MCP App і обмін тікета на сесію в Claude і ChatGPT | Експеримент PoC, гіпотеза 2 |
| Чи Code Mode точніший і дешевший за класичні tools на сценаріях Аури | Після прототипу: у поточному зрізі модель даних не бачить |
| Чи обмежувати видимість контрагентів по фірмах | Власник продукту |
| Модель ліцензування користувачів (Claude Team / ChatGPT Business / Copilot) і порівняння з 1С | Власник продукту, після PoC |
