# 13. Канали доступу і власна модель

Уточнення до [02-архітектура.md](02-архітектура.md), зроблене 2026-10-31. Стосується обох варіантів.

## Принцип уточнено

«Без власного інтерфейсу» — не абсолютна вимога. Принцип звучить так: **жоден інтерфейс не містить бізнес-логіки, усі канали — рівноправні тонкі клієнти одного ядра.** Чат-боти — один із каналів, а не єдиний.

## Три канали, одні SPA

```
                 ┌──────────── Ядро Аури: API + правила + RLS ────────────┐
                 │                                                         │
      MCP-сервер Аури (open_* tools)                              REST для SPA
         ▲                    ▲                                         ▲
         │                    │                                         │
 Claude / ChatGPT     Вбудований чат каталогу                    Каталог SPA
 (зовнішня модель)    (власна модель)                             (клік → SPA)
         │                    │                                         │
         └──────── усі відкривають ті самі SPA ─────────────────────────┘
```

| Канал | Що це | Коли потрібен |
|---|---|---|
| Каталог SPA | Структурований перелік SPA за правами користувача, вхід через Keycloak. Розвиток App Hub з [02](02-архітектура.md) і SPA поза чатом з [09](09-прототип-доступ-і-запуск-spa.md) | Центральний вхід у систему; не залежить від підтримки MCP Apps у клієнтах |
| Claude / ChatGPT | MCP-коннектор, tools запуску SPA | Для тих, хто працює в чат-боті |
| Вбудований чат | Ще один MCP-клієнт власного сервера, працює на власній моделі | Для холдингів, яким зовнішні LLM заборонені; пізніше за каталог |

Наслідки:

- **SPA не залежить від того, хто її запустив.** Одна збірка працює у вікні MCP App, у каталозі і окремою сторінкою. Контракт запуску однаковий: параметри (`project_hint`, `question`…) плюс сесія.
- **Вбудований чат не має своєї логіки.** Він викликає ті самі `open_*` tools, що й Claude.
- **Вбудований чат лишається мінімальним**: відкрити SPA і поставити питання про дані. Конкурувати з Claude і ChatGPT за загальними можливостями (файли, довгі діалоги) він не повинен.

## Питання про дані без передачі даних зовнішній моделі

Якщо модель лише відкриває SPA, головна цінність чат-бота — відповіді на питання на кшталт «яка маржа по бренду X за квартал» — втрачається. Рішення: питання відповідає SPA разом з власною моделлю, а зовнішній чат-бот передає тільки текст питання.

```
Користувач: «яка маржа по бренду X за 3 квартал?»
   │
Claude / ChatGPT ── open_analytics({ question: "маржа по бренду X за 3 квартал" })
   │                      (питання — слова користувача, даних тут немає)
   ▼
SPA «Аналітика» ── питання ──► Аура: власна модель → типізований запит
                                       │
                                       ▼
                                 API аналітики (RLS, права)
   ◄──────── таблиця / графік ─────────────────────────────┘
Claude знає тільки: «Відкрито SPA Аналітика»
```

- **Власна модель не бачить даних.** Вона перетворює питання на типізований запит до API аналітики (не SQL). Сервер перевіряє запит і виконує його з правами користувача; таблицю малює SPA. Текстовий висновок над результатом — окремий необовʼязковий крок, якщо знадобиться.
- **Вихід моделі обмежено JSON-схемою запиту** (structured outputs). Для малих моделей це помітно зменшує кількість зламаних запитів.
- **Дотренування — не на старті.** Спершу опис API, приклади і схема. Дотреновувати тільки якщо оцінка покаже провали.
- **Аудит показує, що бачив зовнішній чат-бот**: тільки текст питання. Це аргумент для демо.

## Слот моделі

Модель підключається через адаптер з API, сумісним з OpenAI. Перемикання — `base_url` і назва моделі в конфігурації.

| Варіант | Якість | Вартість | Де дані |
|---|---|---|---|
| Відкрита модель (Qwen, Gemma) на своєму GPU, vLLM | Достатня для генерації запитів, слабша в складних питаннях | GPU працює постійно | Не покидають систему |
| Відкрита модель як керований сервіс (у т. ч. з розміщенням в ЄС) | Те саме | Оплата за токени | Інфраструктура провайдера за договором |
| Claude / GPT через корпоративний API без зберігання даних | Найвища | Оплата за токени | Інфраструктура провайдера за договором |

Модель, яка лише будує запити, бачить питання, але не дані. Тому для неї можна мати один спільний сервер без стану на кілька екземплярів Аури, а не GPU на кожен холдинг.

## Модель для прототипу

У прототипі немає даних клієнтів, тому ізоляція не потрібна: достатньо загальнодоступного API з оплатою за токени.

| Сервіс | Навіщо |
|---|---|
| **OpenRouter** — основний вибір | Один ключ, API, сумісний з OpenAI, сотні моделей. Модель перемикається одним рядком — зручно порівнювати на наборі питань |
| DeepInfra, Together | Прямі хостинги відкритих моделей, той самий тип API |
| Alibaba Model Studio | Рідний хостинг Qwen; безкоштовні токени на старті |
| Ollama локально | Безкоштовно за наявності відеокарти на 8–12 ГБ |

Орієнтир ціни для моделі класу Qwen3 8B — близько $0.12–0.18 за мільйон вхідних і $0.20–0.70 за мільйон вихідних токенів, залежно від провайдера (агрегатори цін, жовтень 2026; перевіряти на сторінці провайдера). Одне питання — кілька тисяч токенів, тобто частки цента. Весь прототип — долари.

Як вибирати модель:

1. Набір із 50–100 питань з очікуваним запитом — розширення 20–30 сценаріїв PoC.
2. Прогнати на моделі 7–9B і на моделі 14–30B (наприклад, Qwen3 30B-A3B). Різниця покаже, якого розміру достатньо для пілота.
3. Перед стартом перевірити, яка найсвіжіша мала модель доступна: згадуються вже лінійки Qwen 3.7 і 3.8.

## Відкриті питання

| Питання | Як закривається |
|---|---|
| Рівні ізоляції як налаштування холдингу: (1) модель — тільки навігатор, (2) бачить агрегати і статуси, (3) бачить рядки, крім затратної частини | Власник продукту, до демо клієнтам |
| Якого розміру моделі достатньо для генерації запитів аналітики | Оцінка на наборі питань у прототипі |
| Чи входить вбудований чат у пілот, чи тільки каталог і зовнішні чат-боти | Власник продукту, після прототипу |
