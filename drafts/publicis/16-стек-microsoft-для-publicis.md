# 16. Стек технологій для Publicis: Аура 6 в інфраструктурі Microsoft

Варіант — [управлінський облік](../варіант-управлінський-облік/README.md). Стан на 2026-11-08.

Клієнт готовий почати за умови, що система працюватиме в його інфраструктурі Microsoft: Microsoft 365, Teams, Copilot, MS SQL, Azure. Запропонований стек:

- вхід через Microsoft 365;
- MS SQL;
- бекенд на Node.js;
- IIS;
- React + TypeScript;
- Copilot як LLM.

Документ має дві частини. [Частина 1](#частина-1-коротко-для-керівництва) написана для тих, хто приймає рішення, і не потребує технічних знань. [Частина 2](#частина-2-для-іт-служби) призначена для ІТ-служби Publicis.

## Частина 1. Коротко для керівництва

### Висновок

**Стек підходить.** Чотири з шести пунктів приймаються без змін, ще два потребують уточнення:

| Пункт | Підходить? | Простими словами |
|---|---|---|
| Вхід через Microsoft 365 | Так | Працівник входить тим самим обліковим записом, що й у пошту та Teams. Окремих паролів немає. Звільненого працівника вимикають у Microsoft 365, і він автоматично втрачає доступ до Аури |
| MS SQL | Так | Дані лежать у базі Publicis, під контролем ІТ Publicis і з її резервними копіями. У хмарі це Azure SQL. Dataverse — теж база Microsoft, але вона створена для іншого (див. [2.3](#23-база-даних-ms-sql)) |
| Node.js | Так | Поширена технологія, яку Microsoft офіційно підтримує в Azure |
| IIS | Можна, але є краще рішення | IIS працює, проте вимагає більше ручного адміністрування. Якщо Publicis уже користується Azure, Ауру можна розмістити там: оновлення, сертифікати й масштабування Microsoft бере на себе. Якщо політика компанії вимагає власних серверів, підійде й IIS |
| React + TypeScript | Так | Ті самі екрани відкриваються в браузері і в Teams |
| Copilot як LLM | Так, з уточненням | Див. нижче |

### Як Аура використовує штучний інтелект Microsoft

Copilot — це продукт для працівника, чат у Teams і Office. Окремого «двигуна Copilot» для вбудовування у власну систему Microsoft не надає.

Натомість є **Azure OpenAI** — ті самі моделі OpenAI (GPT), на яких працює Copilot, але розгорнуті в хмарі Publicis і доступні для власних систем. Їх і використовує Аура. Помічник в Аурі:

- розуміє питання звичайною мовою і перетворює його на точну інструкцію для бази;
- відкриває потрібний екран і будує звіт;
- пояснює цифри.

**Безпека даних.** Azure OpenAI працює за корпоративними умовами Microsoft, такими самими, як Copilot:

- дані не використовуються для навчання моделей і не потрапляють ні до OpenAI, ні до інших клієнтів Microsoft;
- обробка відбувається в межах ЄС.

Одне застереження. Microsoft автоматично перевіряє запити на зловживання (шкідливий контент). У рідкісних випадках, коли автоматика сумнівається, запит можуть переглянути уповноважені співробітники Microsoft з ЄЕЗ. Для облікових даних це малоймовірно, але Publicis як великий корпоративний клієнт може подати заявку на повне вимкнення такого збереження й перегляду.

Модель отримує лише те, що має право бачити сам працівник, і не може нічого змінити в базі напряму: будь-яку зміну перевіряє сервер Аури. Що саме дозволено передавати моделі (лише питання, підсумки чи рядки), вирішує Publicis — це налаштування системи.

### Як це виглядатиме для працівника

| Де | Що відбувається |
|---|---|
| **Teams** | Вкладка «Аура» в лівій панелі. Каталог екранів: проєкти, медіаплани, заявки, звіти. Вхід автоматичний |
| **Браузер** | Окрема адреса, той самий вхід через Microsoft 365 |
| **Помічник в Аурі** | Панель, де можна спитати звичайною мовою. Помічник відкриває потрібний екран, будує звіт, пояснює цифри |
| **Excel** | Бюджети імпортуються з файлів, що лежать в OneDrive або SharePoint |

Пізніше можна додати агента «Аура» в самому чаті Copilot і звʼязок із листуванням та документами Microsoft 365. Для старту це не потрібно.

### Де дані і хто їх контролює

- Усі дані зберігаються в хмарі або на серверах Publicis, в окремій базі для холдингу.
- Розробник має доступ лише тоді, коли його надає ІТ Publicis, і цей доступ можна обмежити в часі.
- Кожне звернення до моделі записується в журнал: хто питав, що отримала модель, що відповіла.

### Що потрібно від Publicis

1. Рішення, де розміщуємо систему: у хмарі Azure (рекомендуємо) чи на власних серверах з IIS.
2. Підписка Azure або сервер, а також база MS SQL.
3. Адміністратор Microsoft 365, який зареєструє Ауру як корпоративний застосунок і визначить, хто має до неї доступ.
4. Погодження служби безпеки на Azure OpenAI, а також рішення, які дані можна передавати моделі.

### Ризики простими словами

- **ШІ оплачується за використання.** Azure OpenAI тарифікується за обсяг тексту; для управлінського обліку це долари чи десятки доларів на місяць. **Аура працює і без ШІ**: через Teams і браузер.
- **Погодження в групі.** Якщо рішення приймає глобальна ІТ-служба Publicis Groupe, а не локальна, це може зайняти час. Варто зʼясувати якомога раніше.

## Частина 2. Для ІТ-служби

### 2.1 Архітектура

```
        Teams (вкладка)                          Браузер
             │ MSAL + NAA                           │ MSAL (PKCE)
             └──────────────────┬───────────────────┘
                                │  Microsoft Entra ID: токени, MFA, Conditional Access
                                ▼
 ┌──────────── Azure App Service (Linux, Node.js 24 LTS) або IIS ────────────┐
 │  Aura API (REST + OpenAPI)        AI-адаптер: питання → типізований запит, │
 │  Статика SPA (React)              пояснення; дані — з правами користувача  │
 └───────┬──────────────────────────┬──────────────────────────┬─────────────┘
         │ Managed Identity         │ Managed Identity         │
         ▼                          ▼                          ▼
   Azure SQL Database           Azure OpenAI               Microsoft Graph
   (RLS, temporal,              (Foundry,                  (файли SharePoint /
    ledger-аудит)                EU Data Zone)              OneDrive, сповіщення)

   Key Vault · Application Insights · Storage
```

Принципи з [02-архітектура.md](../02-архітектура.md) і [09-прототип-доступ-і-запуск-spa.md](../09-прототип-доступ-і-запуск-spa.md) лишаються без змін:

- бізнес-логіка тільки на сервері, а SPA — тонкі клієнти;
- дві лінії захисту: політика в коді і RLS у БД;
- модель не має прямого доступу до БД. Дані для неї збирає сервер з правами користувача, а будь-яка зміна — типізована команда, яку сервер перевіряє.

### 2.2 Автентифікація: Microsoft Entra ID

Keycloak не потрібен. Обидва — стандартні OIDC-провайдери, тож код Аури від вибору не залежить (див. [03](../03-стек-технологій.md)).

**Реєстрації застосунків** (app registrations):

| Реєстрація | Тип | Для чого |
|---|---|---|
| `aura-api` | Resource (Expose an API) | Scope `access_as_user`; app role `Aura.Admin`. API перевіряє токени через JWKS за `aud`, `iss`, `tid` і `scp` (бібліотека `jose`) |
| `aura-spa` | SPA, PKCE | Вхід у браузері (`@azure/msal-react`). Додатковий redirect `brk-multihub://<домен>` для NAA в Teams і Outlook |

- **Ідентифікатор користувача** — пара `tid` + `oid`. Не `sub`: в Entra він різний для кожного застосунку.
- **Хто може увійти.** Для `aura-api` вмикається *Assignment required*, і застосунок призначається групі на кшталт `Aura-Users`. Хто не в групі, токен не отримає.
- **Права по фірмах** зберігаються в БД Аури, як у [09](../09-прототип-доступ-і-запуск-spa.md): вони змінюються часто і потрібні RLS. Групи Entra можна використати для початкового призначення ролей. Чи синхронізувати їх постійно — відкрите питання.
- **MFA, Conditional Access і журнал входів** застосовуються автоматично.

### 2.3 База даних: MS SQL

**Рекомендація: Azure SQL Database.** Альтернатива — SQL Server 2022/2025 на власних серверах. Усе, що було сплановано для PostgreSQL, має відповідник:

| Задача | Було (PostgreSQL) | Стає (MS SQL) |
|---|---|---|
| RLS — друга лінія захисту | `CREATE POLICY` + `SET LOCAL aura.user_id` | `CREATE SECURITY POLICY` з inline-функціями предикатів (filter + block) і `sp_set_session_context` на початку кожної транзакції. Зʼєднання при поверненні в пул скидається (`sp_reset_connection`), щоб контекст не перейшов іншому користувачу |
| Підключення сервера до БД | Логін і пароль | Managed Identity, без паролів. Роль сервера не має `db_owner` і не може змінити security policy |
| Гроші | `numeric` + decimal.js | `decimal(19,4)`. Типи `money` і `float` не використовуються. Застереження нижче |
| Історія змін робіт | Таблиця історії | System-versioned temporal tables. «Хто змінив» — окрема колонка `changed_by`, бо temporal tables її не зберігають |
| Аудит викликів | Таблиця тільки на дописування | Ledger table (append-only), захищена від підробки, — у Azure SQL і SQL Server 2022+ |
| JSON (параметри, знімки версій плану) | `jsonb` | Нативний тип `json` (Azure SQL, SQL Server 2025) або `nvarchar(max)` + `ISJSON` |
| Фонові задачі | pg-boss, Graphile Worker | Для MVP — черга в таблиці (`UPDLOCK, READPAST`). Пізніше, за потреби, Azure Service Bus |
| Аналітика | View в схемі `analytics` | Те саме. Power BI може підключатися до цих view; RLS для прямого підключення — окреме питання (2.8) |

**Доступ до БД із Node:**

- **Kysely** з офіційним MSSQL-діалектом (`tedious` + `tarn`) — рекомендований варіант, він уже згадувався в [03](../03-стек-технологій.md).
- **Drizzle** підтримує MSSQL лише в бета-гілці v1, тому для продакшену не рекомендується.
- **Prisma** підтримує SQL Server, але це важча ORM, від якої ми відмовились у [03](../03-стек-технологій.md).

Міграції — звичайні SQL-скрипти в репозиторії, щоб DBA Publicis міг їх переглянути.

**Застереження щодо грошей.** Драйвер `tedious` повертає `DECIMAL` як JavaScript `number`. Для сум до ~10¹¹ з 4 знаками після коми цього вистачає, але правило «гроші ніколи не float» формально порушується. На етапі технічного завдання обрати одне з двох:

- (а) у view і запитах читати суми як рядок (`CAST(... AS varchar)`) і далі працювати з decimal.js;
- (б) зберігати суми в мінімальних одиницях як `bigint`, який `tedious` повертає рядком, без втрат.

Агрегати в будь-якому разі рахуються в SQL.

**Чому не Dataverse.** Dataverse — база даних Power Platform: Power Apps, Dynamics 365, Copilot Studio. Технічно вона працює на інфраструктурі Azure, але це окремий продукт зі своїми ліцензіями. Вона зручна для low-code застосунків, проте для ядра Аури не підходить:

| | Azure SQL | Dataverse |
|---|---|---|
| Призначення | Реляційна БД для власних систем | Платформа даних для Power Apps і Dynamics 365 |
| Запити | Повний SQL: транзакції, view, агрегати | Web API (OData) або FetchXML. SQL — тільки читання через TDS-ендпоінт |
| Логіка Аури (розподіл FIFO, перерахунок, версії плану) | В одній транзакції на сервері Аури | Через Web API з лімітами запитів, плагіни на C# або Power Automate — логіка розходиться по платформі |
| Права по фірмах | RLS за нашою моделлю | Власна модель Dataverse: business units, команди, ролі безпеки |
| Вартість | Від ~$15 на місяць за невелику базу | Ліцензії Power Apps для користувачів, а місткість понад включену коштує ~$40 за ГБ на місяць (список, жовтень 2026) |
| Перенесення | Стандартний SQL Server, працює будь-де | Тільки в Power Platform |

Якщо Publicis пізніше захоче будувати власні застосунки в Power Apps над даними Аури, їх можна підключити до Azure SQL через стандартний SQL-конектор або через API Аури. Переносити дані в Dataverse для цього не потрібно.

**Для продукту загалом.** Серверного коду управлінського варіанта ще немає: демо-прототип працює в браузері. Тому перехід на MS SQL зараз майже нічого не коштує. Утримувати дві СУБД в одному продукті (PostgreSQL для одних холдингів, MS SQL для інших) — дорого, бо відрізняються RLS, міграції й типи. Рішення щодо однієї СУБД для продукту — у відкритих питаннях (2.11).

### 2.4 Бекенд: Node.js

- **Node.js 24 LTS.** Для старту наприкінці 2026 року краще брати 24, а не 22: у 22-ї підтримка закінчується у квітні 2027.
- **Fastify або Hono, Zod-контракти, OpenAPI, згенерований TS SDK** — без змін щодо [03](../03-стек-технологій.md).
- **AI-адаптер:** Azure OpenAI через пакет `openai` з Azure-конфігурацією, автентифікація через Managed Identity (`@azure/identity`). Модель змінюється конфігурацією.
- **Моніторинг:** Azure Monitor OpenTelemetry Distro (`@azure/monitor-opentelemetry`) → Application Insights.
- **Секрети** — у Key Vault, через Key Vault references в App Service. У коді й конфігураційних файлах їх немає.

**Чому не .NET.** Це питання ІТ Microsoft-компанії поставить напевно, тож відповідь варто мати заздалегідь. .NET — повноцінна альтернатива, Azure підтримує обидві платформи однаково. Node обрано, щоб мати одну мову з SPA і користувацькими застосунками, які генерують LLM: вони найкраще пишуть саме TypeScript. Якщо Publicis вимагатиме .NET, архітектура не зміниться, але ядро доведеться писати на C#.

### 2.5 Розміщення: IIS чи Azure App Service

Node.js не працює в IIS напряму. Модуль `iisnode` фактично покинутий — нових випусків немає близько девʼяти років, — тож його не використовуємо. Є два робочі варіанти з IIS:

1. **HttpPlatformHandler.** IIS запускає процес Node і проксює на нього запити.
2. **Зворотний проксі.** IIS з URL Rewrite і ARR приймає запити й передає їх Node, який працює як служба Windows (WinSW або NSSM).

Для потокових відповідей помічника (SSE) в ARR треба вимкнути буферизацію відповіді (`responseBufferLimit="0"`).

| | Azure App Service (рекомендуємо) | IIS на своєму сервері або на ВМ в Azure |
|---|---|---|
| Оновлення ОС і Node | Microsoft | ІТ Publicis |
| TLS-сертифікати | Керовані | Вручну |
| Деплой без простою | Deployment slots | Вручну |
| Масштабування | Налаштування | Новий сервер + балансувальник |
| Доступ до Azure SQL без пароля | Managed Identity | На ВМ в Azure — Managed Identity; на власному сервері — Azure Arc або сервісний обліковий запис |
| Коли обирати | Якщо є підписка Azure | Якщо політика вимагає IIS |

**Мережа.** API має бути доступним для працівників:

- або лише з корпоративної мережі чи VPN;
- або з інтернету під захистом Entra і Conditional Access, за потреби — за Azure Front Door із WAF.

Звернення до Azure OpenAI — вихідні, з сервера. База даних закривається Private Endpoint і з інтернету недоступна.

### 2.6 Інтерфейс: React + TypeScript

- **Vite + React + TypeScript.** Демо-прототип уже на цьому стеку.
- **Fluent UI React v9** замість shadcn/ui (рекомендація). Так інтерфейс виглядає рідним у Teams і M365 і автоматично підхоплює світлу, темну й контрастну теми Teams.
- **Вхід:** MSAL React із PKCE. У Teams і Outlook використовується Nested App Authentication (`createNestablePublicClientApplication`): SSO без окремого вікна входу, одна збірка для всіх хостів. NAA тривалий час мав статус preview — перед пілотом перевірити поточний статус. Як запасний варіант лишається звичайний MSAL popup.
- **Teams-застосунок:** маніфест (Microsoft 365 Agents Toolkit або Developer Portal) з персональною вкладкою-каталогом. Адміністратор розгортає його групі через Teams Admin Center.

### 2.7 Штучний інтелект: Azure OpenAI

**Рішення (2026-11-09): стартуємо з `gpt-5.4-mini` в Azure OpenAI, Data Zone EU.** Відкрита модель на власному GPU (Qwen) — запасний варіант, якщо Publicis заборонить моделі OpenAI або знадобляться відкриті ваги чи дотренування.

**Чому Azure OpenAI, а не Copilot.** M365 Copilot — продукт для кінцевого користувача. Його програмний інтерфейс (Work IQ API, колишній Copilot Chat API) призначений для роботи з даними Microsoft 365: повертає текст і працює лише від імені користувача. Для генерації запитів до бази потрібна відповідь за строгою JSON-схемою, а це дає Azure OpenAI. Work IQ — кандидат на після MVP (2.8).

**Налаштування.**

- Тип розгортання — **Data Zone EU**: обробка в межах ЄС.
- **Structured outputs** за JSON-схемою запиту: вихід моделі не може бути зламаним JSON.
- API сумісний з OpenAI, тому адаптер Аури ([13](../13-канали-і-власна-модель.md)) змінює лише `base_url` і назву моделі.

**Захист даних** — за сторінками Microsoft Learn «Data, privacy, and security» і «Abuse monitoring» (оновлені в травні–червні 2026):

| Питання | Що каже Microsoft |
|---|---|
| Навчання моделей | Prompts і completions *«are NOT used… to improve their models»*. Недоступні OpenAI, іншим постачальникам та іншим клієнтам |
| Зберігання в самій моделі | Моделі без стану: запит у моделі не зберігається |
| Abuse monitoring | Автоматичні класифікатори перевіряють запити без збереження. Підозрілі запити можуть потрапити в окреме сховище для перегляду людьми. Сховище розташоване в географії ресурсу; для моделей в ЄЕЗ рецензенти — в ЄЕЗ. Доступ — уповноважені співробітники Microsoft через Just-In-Time-погодження. Строк зберігання в поточній документації не вказано: раніше було «до 30 днів», уточнити в Microsoft |
| Вимкнення (modified abuse monitoring) | Для клієнтів, яких веде account team Microsoft або які входять у відповідну програму. Заявка через форму Microsoft. Після погодження збереження і перегляд людьми не виконуються, автоматичні фільтри працюють. Перевірка: `ContentLogging: false` у властивостях ресурсу |
| Функції зі збереженням у ресурсі | Responses API (за замовчуванням зберігає відповідь 30 днів), Assistants, stored completions, файли, batch, fine-tuning. Дані — в ресурсі Publicis, у його географії, з шифруванням AES-256. **Аура їх не використовує**: виклики без стану, Responses API — з `store: false` |

Власний журнал викликів моделі веде Аура, у БД Publicis (2.9). Тому сховище Microsoft для аудиту не потрібне.

**Доступні моделі.** Нижче — моделі з Data Zone EU за сторінками Microsoft Learn «Foundry Models sold by Azure» (оновлені в жовтні 2026). Перед розгортанням звірити в порталі Foundry.

| Модель | Data Zone EU | Роль в Аурі |
|---|---|---|
| `gpt-5.4-mini` | Усі регіони ЄС, крім North Europe | **Обрана для старту**: питання → типізований запит. Швидка й дешева |
| `gpt-5.4`, `gpt-5.5` | Усі 10 регіонів ЄС | Складні питання, пояснення результатів |
| GPT-5.6 (`sol`, `terra`, `luna`), GPT-6 (`astra`, `sol`, `luna`), GPT-6.1 (`sol`, `terra`) | Усі, крім North Europe (`gpt-6-astra` — усі) | Найновіші. Обирати за результатами оцінки на наборі питань |
| `gpt-5`, `gpt-5-mini`, `gpt-5-nano` | Більшість регіонів ЄС | Попереднє покоління |
| `text-embedding-3-large`, `text-embedding-3-small` | Більшість регіонів ЄС | Необовʼязково: пошук за схожими назвами («Альфа» → «ТОВ Альфа-Медіа») |

- **Structured outputs** у таблицях можливостей зазначено для всіх GPT-5.x і GPT-6.x, крім `gpt-5.4-pro`.
- **Без Data Zone EU:** pro-моделі, codex-моделі, `gpt-5.2`. В ЄС вони доступні лише як Global Standard, тобто з обробкою в будь-якому регіоні світу.
- **Інші постачальники**, яких продає Azure: DeepSeek, Grok (xAI), Llama, Mistral, Phi, Cohere. Data Zone EU для них не перевіряли. Claude доступний у Foundry, але на середину 2026 року без EU Data Zone.

**Альтернатива: відкрита модель на власному GPU в Azure.** Наприклад, Qwen3 30B-A3B або новіша модель того ж класу. Варіанти розгортання:

| Варіант | Як | Особливості |
|---|---|---|
| Foundry Managed Compute | Модель з колекції Hugging Face у каталозі Foundry (документований приклад — Qwen3 32B), керований ендпоінт | Preview. Окрема квота на A100 або H100. Content filtering і abuse monitoring Microsoft не входять у шлях даних |
| Azure Container Apps, serverless GPU | Власний контейнер з vLLM на A100 80 ГБ | Посекундна оплата, масштабування до нуля, але холодний старт — хвилини (завантаження ваг). Sweden Central підтримується |
| ВМ NC A100 v4 / NC H100 v5 або AKS | vLLM на ВМ | Повний контроль, адміністрування — на ІТ |

- **Залізо.** Qwen3 30B-A3B — MoE: ~30 млрд параметрів, ~3 млрд активних на токен.
  - BF16 (~61 ГБ) вміщується в один A100 80 ГБ, але місця під контекст мало.
  - FP8 (~31 ГБ) комфортно працює на A100 80 ГБ або H100.
  - 4-bit (~17 ГБ) вміщується в GPU на 24 ГБ.
- **Вартість ВМ з A100** — близько $3.7 на годину (East US, вересень 2026; у регіонах ЄС зазвичай дорожче). Цілодобово це ~$2 700 на місяць, лише в робочі години — ~$800.
- **Плюс** — дані не виходять за межі ВМ Publicis, жодного збереження на боці Microsoft.
- **Мінуси** — фіксована оплата за GPU незалежно від навантаження, доступність квоти на A100/H100 у ЄС, адміністрування.
- **Висновок.** Для обсягів управлінського обліку `gpt-5.4-mini` за токени дешевший на порядок. Власний GPU виправданий, якщо Publicis забороняє моделі OpenAI, вимагає відкритих ваг або дотренування.

**Вибір моделі** — як у [13](../13-канали-і-власна-модель.md): набір із 50–100 питань з очікуваним запитом, прогін на `gpt-5.4-mini` і на одній старшій моделі. Різниця покаже, чи вистачає дешевої.

**Що бачить модель — налаштування холдингу** (рівні ізоляції з [13](../13-канали-і-власна-модель.md)):

| Рівень | Модель отримує | Можливості |
|---|---|---|
| 1 | Тільки питання | Пошук, звіти, відкриття екранів. Цифри показує SPA |
| 2 | Питання + підсумки (суми по проєкту, бренду, періоду) | + пояснення і висновки |
| 3 | Питання + рядки, крім закритих полів (наприклад, затратної частини) | + аналіз окремих робіт |

На всіх рівнях модель отримує тільки те, що має право бачити користувач, і нічого не записує сама. Кожен виклик моделі журналюється: користувач, рівень, обсяг переданих даних, відповідь.

**Copilot connectors** (раніше Graph connectors), тобто індексація даних Аури в Microsoft Graph для Copilot, не використовуються: це копія облікових даних з окремою моделлю прав.

### 2.9 Безпека і відповідність: чек-лист для ІТ

- **Окремий екземпляр для холдингу**: власна resource group або підписка в тенанті Publicis.
- **Регіон Azure** обирає ІТ Publicis: West Europe, Sweden Central, Poland Central тощо.
- **Шифрування:** TDE на БД (увімкнено за замовчуванням), TLS 1.2+.
- **Резервні копії:** Azure SQL point-in-time restore на 7–35 днів, довгострокове зберігання — за політикою.
- **Аудит** на трьох рівнях:
  - аудит Аури (ledger table): користувач, канал, дія, фірма, результат, виклики моделі;
  - Azure SQL Auditing;
  - журнал входів Entra.
- **Доступ розробника:** гостьовий обліковий запис Entra (B2B) і PIM, тобто права адміністратора на обмежений час і за запитом.
- **Середовища** dev, test і prod. CI/CD — GitHub Actions або Azure DevOps з federated credentials, без секретів у конвеєрі.

### 2.10 Що змінюється порівняно з попередніми документами

| Компонент | Було ([03](../03-стек-технологій.md), [08](../08-підготовка-до-прототипу.md), [09](../09-прототип-доступ-і-запуск-spa.md), [13](../13-канали-і-власна-модель.md)) | Для Publicis |
|---|---|---|
| Ідентифікація | Keycloak | Microsoft Entra ID |
| БД | PostgreSQL | Azure SQL Database або SQL Server |
| RLS | `SET LOCAL` + policies | `SESSION_CONTEXT` + security policy |
| Фонові задачі | pg-boss | Черга в таблиці, потім Service Bus |
| Розміщення | VPS + Docker Compose + Caddy | Azure App Service або IIS |
| Канали | Каталог SPA, зовнішні чат-боти, вбудований чат | Каталог SPA у Teams і браузері, помічник в Аурі. Агент у Copilot — пізніше |
| Модель | OpenRouter (прототип), vLLM | Azure OpenAI (Foundry, EU Data Zone) |
| UI-кіт | shadcn/ui | Fluent UI v9 |

**Не змінюються:**

- ядро API і Zod-контракти;
- SPA як тонкі клієнти;
- правило FIFO для розподілу оплат;
- модель даних з [12](../варіант-управлінський-облік/12-варіант-управлінський-облік-проєктів.md).

### 2.11 Відкриті питання до Publicis

| Питання | Чому важливо |
|---|---|
| Azure чи власні сервери з IIS? | Від цього залежать розміщення, мережа і доступ до БД без паролів |
| Хто погоджує — локальна ІТ чи ІТ групи? | Строки старту |
| Чи дозволено Azure OpenAI в підписці Publicis, і в якому регіоні? | Помічник в Аурі |
| Чи подавати заявку на modified abuse monitoring? | Повне виключення збереження і перегляду запитів людьми з боку Microsoft (2.7) |
| Який рівень ізоляції: що можна передавати моделі? | Від цього залежить, що вміє помічник (2.7) |
| Окремий екземпляр SQL чи наявний кластер? | Ізоляція, резервні копії, вартість |
| Чи призначати доступ до фірм через групи Entra? | Хто адмініструє права: ІТ в Entra чи адміністратор Аури |
| Яка бухгалтерська система (для майбутньої інтеграції платежів)? | Не входить у MVP, але впливає на модель даних |

Внутрішнє питання до власника продукту: **одна СУБД для всього продукту чи дві?** SQL Server працює й на Linux у Docker, тож MS SQL можна зробити базовою СУБД для всіх холдингів. Ціна такого рішення — ліцензії SQL Server у холдингів без Microsoft-інфраструктури: Express безкоштовний, але має ліміт 10 ГБ на базу.

### 2.12 Кроки пілоту

1. Resource group, реєстрації застосунків в Entra, група `Aura-Users`.
2. Azure SQL: схема управлінського варіанта, RLS, temporal tables, ledger-аудит. Тести доступу з вимкненою першою лінією захисту, як у [09](../09-прототип-доступ-і-запуск-spa.md).
3. API і SPA в App Service. Вкладка в Teams для пілотної групи.
4. Azure OpenAI: розгортання `gpt-5.4-mini` (Data Zone EU), помічник в Аурі. Оцінка генерації запитів на наборі питань; старша модель — лише якщо оцінка покаже провали (2.7).
